# Research notes: profiles worth studying

This design intentionally avoids generator-style profiles. The useful references were profiles where the mechanism itself says something about the engineer.

## Standout references

- [Tim Burgan](https://github.com/timburgan/timburgan) turns a README into community chess. Moves open pre-filled issues; Actions validate them and rewrite the board. It stands out because the profile is a working social system, not a decorated biography.
- [Andrew Healey](https://github.com/Andrew6rant/Andrew6rant) treats the profile as a self-updating `neofetch` screen. The strong idea is provenance: his own Python and Actions compute the data, with separate light/dark SVG assets, instead of outsourcing identity to generic cards.
- [Evaristo Cuesta](https://github.com/evaristocuesta/evaristocuesta) implements Minesweeper through GitHub workflows. It demonstrates that issues, commits, and Actions can become an interaction model despite README sandboxing.
- [Simon Willison](https://github.com/simonw/simonw) generates recent releases, projects, and writing. It is visually quiet but exceptionally high-signal: dynamic content proves ongoing work without ornamental statistics.
- [lowlighter](https://github.com/lowlighter/lowlighter) makes the profile an information canvas generated by the Metrics project. Its lesson is composition and density control—many live sources can still form a coherent visual system.
- [ouuan](https://github.com/ouuan/ouuan) uses generated graphics and careful repository automation as a cohesive personal surface. It feels authored rather than assembled.
- [Platane/snk](https://github.com/Platane/snk) converts the contribution graph into an animated SVG. The important innovation is semantic motion: animation is derived from real GitHub data.
- [brunnerlivio](https://github.com/brunnerlivio/brunnerlivio) is a classic example of using a profile as a generated content surface rather than a static “about me” page.

## Community and implementation findings

- In a [Reddit inspiration discussion](https://www.reddit.com/r/github/comments/uulygm/what_are_some_really_nice_github_profile_readmes/), the strongest recurring preference is for clean profiles whose gimmick is purposeful; Andrew6rant’s Action-refreshed, theme-aware `neofetch` was singled out.
- The [self-updating README discussion](https://www.reddit.com/r/github/comments/p2oyf7/i_made_a_selfupdating_github_readme/) shows why authored automation is memorable: even a small daily computation makes the repository itself part of the portfolio.
- [DEV’s custom SVG widget guide](https://dev.to/iammastercraft/build-your-own-github-profile-widgets-from-scratch-2e3h) confirms the robust deployment choices: pre-generate SVGs with Actions, avoid scripts and `foreignObject`, and test the raw SVG through GitHub’s renderer.
- [GitHub’s documentation](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/managing-your-profile-readme) confirms the delivery constraint: the public repository must match the account username and contain a root `README.md`.

X/Twitter results were mostly reposts and generator promotion with poor source durability. They did not materially improve the source set, so no design decision rests on them.

## Synthesis used for Nour

1. **One authored metaphor:** an observability/control-plane surface fits backend, distributed-systems, and ML infrastructure goals.
2. **Semantic animation:** packets move through a request trace and architecture path; motion explains the system.
3. **Self-owned telemetry:** a dependency-free Python script and GitHub Action generate the live panel from GitHub’s API.
4. **Recruiter-readable hierarchy:** thesis, current state, capability map, live proof, engineering values.
5. **Restraint:** no visitor count, quote, trophy wall, generic badges, skill-logo carpet, or third-party uptime dependency.
